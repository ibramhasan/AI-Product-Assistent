# Delivery Thinking Tests

This document defines the expected behavior of the Delivery Thinking capability.

---

# Happy Path

## DT-HP-001 — Recommend a Delivery Approach

### Intent

Recommend an effective delivery approach for a Product Increment.

### User Input

We have completed Product Backlog refinement. Help us determine the best way to deliver this Increment.

### Expected Capability

Delivery Thinking

### Expected Artifact

Delivery Recommendation

### Expected Behavior

- Review the Increment objective.
- Review the Product Backlog Items.
- Identify delivery risks.
- Recommend an appropriate delivery approach.
- Produce a Delivery Recommendation.

### Should Not

- Create implementation tasks.
- Assign work to developers.
- Modify the Product Goal.

### Success Criteria

- Produces a Delivery Recommendation.
- Explains delivery rationale.
- Identifies delivery risks.

### Failure Criteria

- Creates Sprint tasks.
- Assigns work to individuals.
- Produces implementation instructions.

---

## DT-HP-002 — Identify Delivery Risks

### Intent

Identify delivery risks before implementation begins.

### User Input

Before we start implementation, help us identify potential delivery risks.

### Expected Capability

Delivery Thinking

### Expected Artifact

Delivery Recommendation

### Expected Behavior

- Assess delivery dependencies.
- Identify delivery risks.
- Recommend mitigation strategies.
- Produce a Delivery Recommendation.

### Should Not

- Ignore dependencies.
- Recommend implementation details.

### Success Criteria

- Clearly identifies delivery risks.
- Provides practical mitigation recommendations.

### Failure Criteria

- Omits major delivery risks.

## DT-HP-003 — Recommend Increment Sequencing

### Intent

Recommend an effective sequence for delivering an Increment.

### User Input

Several Product Backlog Items are ready. Help us determine the best delivery sequence.

### Expected Capability

Delivery Thinking

### Expected Artifact

Delivery Recommendation

### Expected Behavior

- Review Product Backlog Items.
- Identify dependencies.
- Recommend delivery sequencing.
- Explain the rationale.
- Produce a Delivery Recommendation.

### Should Not

- Prioritize Product Strategy.
- Redesign the Increment.

### Success Criteria

- Delivery sequence is logical.
- Dependencies are considered.

### Failure Criteria

- Ignores dependencies.

## DT-HP-004 — Recommend a Release Approach

### Intent

Recommend an appropriate release strategy.

### User Input

### Expected Capability

Delivery Thinking

### Expected Artifact

Delivery Recommendation

### Expected Behavior

- Evaluate release alternatives.
- Explain trade-offs.
- Recommend an appropriate release approach.
- Produce a Delivery Recommendation.

### Should Not

- Design implementation.

### Success Criteria

- Explains release trade-offs.
- Produces a Delivery Recommendation.

### Failure Criteria

- Chooses a release approach without explanation.

## DT-HP-005 — Prepare for Delivery Execution

### Intent

Prepare the Product Team for delivery execution.

### User Input

We have completed backlog refinement. Help us prepare for delivery.

### Expected Capability

Delivery Thinking

### Expected Artifact

Delivery Recommendation

### Expected Behavior

- Review delivery readiness.
- Identify remaining delivery concerns.
- Recommend next delivery activities.
- Produce a Delivery Recommendation.

### Should Not

- Perform Sprint Planning.
- Assign work.
- Estimate individual effort.

### Success Criteria

- Produces a Delivery Recommendation.
- Explains delivery readiness.

### Failure Criteria

- Creates Sprint assignments.
- Allocates work to individuals.
