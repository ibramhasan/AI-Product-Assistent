# Increment Design Tests

This document defines the expected behavior of the Increment Design capability.

---

# Happy Path

## ID-HP-001 — Design the Next Product Increment

### Intent

Design the next Product Increment to achieve the Product Goal.

### User Input

We have decided to improve customer onboarding. Help us define the next Product Increment.

### Expected Capability

Increment Design

### Expected Artifact

Increment Specification

### Expected Behavior

- Understand the Product Goal.
- Define the objective of the Increment.
- Identify the expected customer outcome.
- Describe the Increment at a high level.
- Produce an Increment Specification.
- Recommend the next capability.

### Should Not

- Create Product Backlog Items.
- Estimate effort.
- Plan a Sprint.

### Success Criteria

- Produces an Increment Specification.
- Defines the Increment objective.
- Aligns the Increment with the Product Goal.
- Recommends Backlog Engineering as the next capability.

### Failure Criteria

- Creates detailed backlog items.
- Produces implementation tasks.
- Begins Sprint Planning.

## ID-HP-002 — Define Increment Scope

### Intent

Define the scope of the next Increment.

### User Input

Our next release should improve the checkout experience. Help us define the Increment scope.

### Expected Capability

Increment Design

### Expected Artifact

Increment Specification

### Expected Behavior

- Clarify the intended outcome.
- Define Increment boundaries.
- Explain what is included and excluded.
- Produce an Increment Specification.

### Should Not

- Define technical implementation.
- Estimate development effort.

### Success Criteria

- Clearly defines Increment scope.
- Identifies included and excluded work.
- Produces an Increment Specification.

### Failure Criteria

- Scope is ambiguous.
- Includes implementation details.

---

## ID-HP-003 — Describe Expected Customer Value

### Intent

Describe the customer value delivered by the Increment.

### User Input

We want the next Increment to reduce customer onboarding time.

### Expected Capability

Increment Design

### Expected Artifact

Increment Specification

### Expected Behavior

- Describe expected customer value.
- Explain how the Increment supports the Product Goal.
- Produce an Increment Specification.

### Should Not

- Design technical architecture.
- Create implementation tasks.

### Success Criteria

- Customer value is explicit.
- Product Goal alignment is clear.

### Failure Criteria

- Focuses only on technical delivery.

---

## ID-HP-004 — Validate Increment Alignment

### Intent

Ensure the Increment aligns with the Product Goal.

### User Input

We have several ideas for the next release. Help us determine which belong in the same Increment.

### Expected Capability

Increment Design

### Expected Artifact

Increment Specification

### Expected Behavior

- Evaluate proposed work.
- Assess alignment with the Product Goal.
- Define a coherent Increment.
- Produce an Increment Specification.

### Should Not

- Prioritize Product Backlog Items.
- Build a roadmap.

### Success Criteria

- Increment has a coherent objective.
- Scope aligns with the Product Goal.

### Failure Criteria

- Increment contains unrelated work.
