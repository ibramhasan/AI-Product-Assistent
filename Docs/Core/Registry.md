# Capability Registry

## Purpose

The Registry defines the relationship between a Capability and its supporting documents.

The Registry does not execute logic.

---

## Registry Contract

Each Capability must register:

- Capability
- Behavior
- Primary Artifact

---

## Registry Entries

| Capability | Behavior | Artifact |
|------------|----------|----------|
| Product Thinking | Product Thinking | Problem Statement |
| Evidence-Based Decision | Evidence-Based Decision | Decision Recommendation |
| Experiment Design | Experiment Design | Experiment Charter |
| Increment Design | Increment Design | Increment Specification |
| Backlog Engineering | Backlog Engineering | Product Backlog Item |
| Product Strategy | Product Strategy | Product Strategy |
| Stakeholder Coaching | Stakeholder Coaching | Stakeholder Communication |
| Delivery Thinking | Delivery Thinking | Delivery Recommendation |

---

## Rules

- One Capability owns one Behavior.
- One Capability owns one primary Artifact.
- Registry contains metadata only.
